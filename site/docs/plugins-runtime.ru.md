## Фреймы

Весь код плагина выполняется в изолированных фреймах внутри чата, у каждого свой пустой источник (origin). У плагина бывают фреймы нескольких видов:

| Фрейм | Что в нём выполняется | `glaze.plugin.kind` |
|---|---|---|
| Основной | Скрипт `main`. Невидим. Регистрирует хуки, действия и обработчики файлов. | `main` |
| Панель чата | HTML панели с `placement: "chat"`. | `panel` |
| Панель сообщения | HTML панели с `placement: "message"`, по фрейму на каждое сообщение. | `message` |
| Обработчик файлов | `scripts` обработчика файлов, пока он обрабатывает файл. | `file` |

Фреймы создаются, когда открывается чат, и пересоздаются, когда плагины ставят, включают или выключают, когда пользователь меняет настройки плагина или выключает одно из его разрешений. Всё, что хранилось только в переменной JavaScript, при этом пропадает: важное держите в [переменных](#docs/plugins-api/glaze-variables), файлах или `localStorage`.

Что работает во фрейме:

- `localStorage`: свой у каждого плагина, хранится приложением, до 10 МБ. Других хранилищ браузера (cookies, IndexedDB, `sessionStorage`) нет.
- Сетевые запросы, в рамках [правил доступа в интернет](#docs/plugins-permissions/сеть).
- `console.log`: в консоли WebView при отладке.

Основной скрипт — один файл: если код разбит на модули, соберите его в один.

## Хуки

Хуки позволяют плагину участвовать в отправке и генерации. Регистрировать их может только основной скрипт, через `glaze.plugin.on(name, handler)`; `on` возвращает функцию, которая снимает обработчик.

| Хук | Когда | Что может | Нужно |
|---|---|---|---|
| `send:before` | Пользователь отправляет сообщение, до того как оно попадёт в чат. | Изменить `event.text`; вызвать `event.cancel(reason)`, чтобы отменить отправку. Причина показывается пользователю. | `composer` |
| `generation:prepare` | Генерируется ответ, до сборки промпта. | Изменить `event.text` — последнее сообщение пользователя в том виде, в каком его увидит модель. Сам чат не меняется. | `generate` |
| `generation:success` | Ответ готов, но ещё не сохранён. | Изменить `event.text` — сам ответ. Сделать его пустым нельзя. | `generate` |

```js
glaze.plugin.on('generation:prepare', async (event) => {
  const note = await glaze.variables.get('note');
  if (note) event.text += `\n\n(${note})`;
});
```

Обработчик может быть `async`. Обработчики выполняются по очереди, каждый видит текст после предыдущих. Если обработчик выбросил ошибку, его изменения отбрасываются. У обработчиков `send:before` и `generation:success` есть 5 секунд; у `generation:prepare` своего лимита нет, но не затягивайте: ответ их ждёт.

У каждого события есть также `type`, `chatId`, `source` (что его запустило) и `at` (время в формате ISO 8601); у хуков генерации — `generationId`.

## События

События сообщают плагину, что произошло; изменить они ничего не могут. Слушать их могут основной скрипт и панели.

| Событие | Когда | Поля | Нужно |
|---|---|---|---|
| `send:after` | Сообщение отправлено. | `text`, `source` | `composer` |
| `generation:error` | Генерация не удалась. | `generationId`, `error` | `generate` |
| `generation:cancelled` | Пользователь остановил генерацию. | `generationId` | `generate` |
| `chat:opened` | Открыт чат. | `chat` | `messages` |
| `chat:updated` | Изменились название чата, персона, пресет или лорбуки. | `chat` | `messages` |
| `chat:closed` | Пользователь ушёл из чата. | | `messages` |
| `message:added` | Появилось сообщение. | `message`, `change` | `messages` |
| `message:updated` | Сообщение отредактировали или выбрали другой вариант. | `message`, `change` | `messages` |
| `message:deleted` | Сообщение удалено. | `message` (только `id`), `change` | `messages` |
| `message:changed` | Любое из трёх выше. | как выше | `messages` |

У всех событий есть `chatId` и `at`. Как устроены `chat` и `message`, описано в [справочнике API](#docs/plugins-api/glaze-messages).

```js
glaze.plugin.on('message:added', ({ message }) => {
  if (message.role === 'assistant') console.log('Новый ответ', message.id);
});
```

## Действия

Обработчики действий из манифеста регистрирует основной скрипт:

```js
glaze.plugin.onComposerAction('tone', async () => {
  const text = await glaze.composer.get();
  const answer = await glaze.ui.select(['Официально', 'Непринуждённо'], 'Тон');
  if (!answer) return;
  await glaze.composer.set(await glaze.generate(`Перепиши в тоне «${answer}»:\n${text}`));
});

glaze.plugin.onToolsAction('count', async () => { /* ... */ });

glaze.plugin.onMessageAction('rate', async ({ chatId, messageId, role }) => { /* ... */ });
```

Если обработчик выбросил ошибку, пользователь увидит, что действие не удалось, и текст ошибки. Если обработчика для действия нет, пользователю тоже об этом скажут.

## Сообщения между фреймами

Фреймы одного плагина могут общаться: `glaze.plugin.emit(name, detail)` доставляет `detail` в другие фреймы плагина, а они слушают его через `glaze.plugin.on(name, handler)`. Любое имя, которое не совпадает с хуками и событиями выше, принадлежит плагину. `detail` должен быть JSON.

```js
// панель
glaze.plugin.emit('mood:set', { mood: 'happy' });

// основной скрипт
glaze.plugin.on('mood:set', ({ mood }) => glaze.variables.set('mood', mood));
```

Другие плагины этих сообщений не получают. Чтобы обмениваться данными между плагинами, используйте переменные `shared`.

## Панели

**Панель чата** накрывает всю страницу чата, но нажатия принимает только то, что она нарисовала; всё остальное проходит в чат. Оставляйте фон страницы прозрачным и располагайте элементы через `position: fixed`.

Поверх чата лежат элементы приложения: строка состояния, шапка, поле ввода. Их размеры есть в CSS-переменных и в `glaze.ui.insets()`:

| Переменная | `insets()` | Что это |
|---|---|---|
| `--glaze-inset-top-safe` | `topSafe` | Строка состояния. |
| `--glaze-inset-top-bar` | `topBar` | Откуда сверху можно начинать содержимое. Пока совпадает со строкой состояния: панели рисуются поверх шапки приложения. |
| `--glaze-inset-bottom-input` | `bottomInput` | Поле ввода (и клавиатура, когда она открыта). |
| `--glaze-inset-bottom-safe` | `bottomSafe` | Системная область жестов. |

```css
.hud {
  position: fixed;
  right: 12px;
  bottom: calc(var(--glaze-inset-bottom-input) + 12px);
}
```

То, что рисует панель, видно и поверх элементов приложения. Небольшие закреплённые элементы, например плавающие кнопки, возвращаются в промежуток между строкой состояния и полем ввода, если оказались за ними (например, после перетаскивания).

**Панель сообщения** стоит внутри сообщения, до или после его текста (`slot`). Её высота подстраивается под содержимое. `glaze.plugin.messageId` — id этого сообщения, и область `message` у переменных по умолчанию относится к нему.

### Файлы пакета в панели

У фрейма нет собственного адреса, поэтому относительные пути не работают. Ссылайтесь на файлы пакета как `/plugins/<id плагина>/<путь>`; Glaze встроит их в страницу:

```html
<link rel="stylesheet" href="/plugins/example.mood/style.css">
<script src="/plugins/example.mood/panel.js"></script>
<img src="/plugins/example.mood/images/smile.png">
```

Собственные файлы плагина (`glaze.files`) можно указывать в `src`, `href` и `poster` по их пути, например `<img src="files/chat/portrait.png">`. Для этого нужно разрешение `files`.

## Обработчики файлов

Обработчик из `fileHandlers` в манифесте регистрируется в коде с тем же `id`:

```js
glaze.plugin.registerFileHandler('docx', {
  async extract(file, { signal }) {
    // file: { path, name, mimeType, size }
    const base64 = await glaze.files.load(file.path, { encoding: 'base64' });
    return { content: convertToText(base64) };
  },
});
```

Когда пользователь прикрепляет файл такого типа, Glaze кладёт его в `files/tmp` плагина и вызывает `extract`, который возвращает текст для сообщения. Чтобы прочитать файл, нужно разрешение `files`. Если обработчик не может разобрать именно этот файл, он выбрасывает ошибку с `code: 'unsupported_format'`, и Glaze пробует следующий обработчик. На работу у обработчика 10 минут.
