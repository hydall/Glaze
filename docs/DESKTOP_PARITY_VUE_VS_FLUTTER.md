# ПК-интерфейс: `nightly` (Flutter) vs `zzarchive/legacy-vue` (эталон)

> **Статус: расхождения устранены.** Документ описывает состояние `nightly` на
> момент анализа и служит картой того, что было исправлено. Реализация — в этой
> же ветке; сводка внесённых изменений в конце, в разделе
> «Что сделано». Пункты, оставшиеся сознательно нереализованными, там же
> перечислены отдельно.

Сравнение десктопного (≥768px) интерфейса Flutter-ветки `nightly` с архивной
Vue + Capacitor + Electron веткой `zzarchive/legacy-vue`. Vue здесь — эталон:
всё, что описано как «нет / отличается», это отставание Flutter, если явно не
помечено иначе (⭐ — там, где Flutter лучше).

Сравнивались только слои представления ПК-режима. Логика генерации, БД,
промпт-билдер, расширения и т.п. не рассматривались — во Flutter они ушли
далеко вперёд и к теме не относятся.

Ссылки на код даны как `путь:строка`. Vue-пути указаны относительно корня
ветки `zzarchive/legacy-vue`.

## 1. TL;DR — десять главных расхождений

1. **ПК-режим выключен по умолчанию.** Во Flutter `forceMobileLayout` по
   умолчанию `true`, в Vue — `false`. То есть свежая установка на Windows
   показывает мобильный интерфейс, пока пользователь сам не найдёт тумблер.
2. **Шиты не открываются внутри правого сайдбара.** Механизм
   (`showSheetInRightSidebar`) написан, но не вызывается ни из одного места —
   мёртвый код. Все шиты открываются как мобильные `showModalBottomSheet`
   на всю ширину окна.
3. **Свёрнутый правый сайдбар в чате — декоративная иконка.** В Vue это
   рабочая полоса всех иконок Magic Drawer.
4. **Полоса иконок рядом с открытым шитом отсутствует** (Vue: `has-left-strip`).
5. **Инструменты из правого сайдбара открываются в центральной колонке**
   (`context.push('/tools/...')`), а не внутри сайдбара, как в Vue.
6. **Плавающее окно без шапки, заголовка, поиска и кнопки закрытия**;
   внутренняя навигация (Настройки, Темы, О программе) уходит в центральную
   колонку под окном, а не переключает содержимое окна.
7. **Нет ограничения ширины чата** (`--chat-max-width` + две перетаскиваемые
   границы колонки чата).
8. **Нет десктопных дропдаунов** вместо нижних шитов для простых выборов.
9. **Нет реакции на правую кнопку мыши** и нет глобальных горячих клавиш
   (в Vue Escape — иерархическое закрытие, ПКМ — контекстное меню на карточках,
   чатах и сессиях).
10. **Сайдбары не участвуют в теме**: плоский `Colors.black @ 20%` без стекла,
    без `--element-blur`, без `ui-bg` темы; в Vue — полупрозрачное стекло.

## 2. Каркас ПК-раскладки

### 2.1 Что совпадает

* Порог переключения 768px — одинаковый (`desktop_shell.dart:53`,
  `useAppNavigation.js:13`).
* Три колонки: левый сайдбар / центр / правый сайдбар.
* Нижняя навигация скрыта на ПК (`shell_screen.dart:74` возвращает
  `navigationShell` без `Scaffold`/`GlassNavBar`; Vue —
  `desktop.css` `.desktop-mode .footer-container { display: none }`).
* Шапка занимает только центральную колонку и накладывается поверх контента.
* Шапка на ПК не прячется при скролле и не имеет скруглений/полей
  (`GlazeAppBar(borderRadius: BorderRadius.zero)`).
* `/` на ПК редиректится на `/characters` (`router.dart:132`), как и в Vue
  (`useAppNavigation.js:14`).

### 2.2 Расхождения

| # | Тема | Vue (эталон) | Flutter (`nightly`) | Приоритет |
|---|---|---|---|---|
| 2.1 | Дефолт ПК-режима | `forceMobileLayout` = `false` (`APPSettings.js:30`) — ПК-раскладка включается сама | `@Default(true) bool forceMobileLayout` (`app_settings_provider.dart:52`) — ПК-раскладка выключена, пока не включат вручную | **Критично** |
| 2.2 | Переключение при ресайзе окна | `checkDesktop()` следит за `resize` и мигрирует `currentView` (`view-dialogs` → `view-characters`) | `LayoutBuilder` пересобирает раскладку, но маршрут `/` не мигрирует: при растягивании окна из мобильного в ПК остаёшься на `/` с пустой центральной колонкой (в левом сайдбаре тот же список чатов) | Средний |
| 2.3 | Первый кадр | раскладка синхронна | контроллеры сайдбаров грузятся из `SharedPreferences` асинхронно (`desktop_shell.dart:38-45`); до этого рендерится мобильная раскладка → видимый «прыжок» при старте | Средний |
| 2.4 | Escape | глобальный `keydown` → иерархическое закрытие: клавиатура → шит → FS-редактор → SheetView → drawer → поиск → выделение → просмотрщик → onboarding → кнопка «назад» (`useAppNavigation.js:110-207`) | только стандартный `DismissIntent` Flutter (закрывает модальные маршруты). Плавающее окно и поповер глоссария — не маршруты, Escape их не закрывает | Высокий |
| 2.5 | Переход по вкладкам из сайдбара | смена `currentView` | `context.go('/characters')` вместо `navigationShell.goBranch(...)` (`desktop_left_sidebar.dart:80`) — состояние ветки (скролл, фильтры) может теряться | Средний |

## 3. Левый сайдбар

### 3.1 Состав и порядок элементов

**Vue** (`DesktopLeftSidebar.vue`):

```

├ Новый чат            (синяя, вверху)
├──────────────────────
│ DialogList (список чатов)          ← поиск приходит из шапки
```

**Flutter** развёрнутый (`desktop_left_sidebar.dart:137-210`):

```
┌ Поле поиска          ⭐ (в Vue поиск живёт в шапке)
├──────────────────────
│ ChatHistoryList
├──────────────────────

├ Глоссарий
└ Ещё
```

**Flutter** свёрнутый (`desktop_left_sidebar.dart:213-238`):

```
┌ Персонажи  (иконка)
├ Новый чат  (иконка)
├──────────────────────
│ ChatHistoryList(collapsed)
├──────────────────────
├ Глоссарий
└ Ещё
```

## 5. Ресайз сайдбаров

### 6.3 Десктопные дропдауны — **отсутствуют целиком**

В Vue есть `DesktopPopup.vue` (713 строк) + `desktopPopupState.js`: на ПК
простые выборы (списки действий, пикеры, короткие инпуты) открываются не
нижним шитом, а **дропдауном у курсора**:

* глобальный трекер последней позиции `mousedown`/`touchstart`
  (`desktopPopupState.js:44-64`) — вызывающему коду не нужно передавать якорь;
* расчёт позиции с переворотом по обеим осям и прижатием к краям окна
  (`recalcPosition`, `PADDING = 12`);
* оценка высоты по составу (`title`, `bigInfo`, `items`, `sessionItems`,
  `cardItems`, `input`) и `transform-origin` под направление раскрытия;
* два дизайна: обычный (220px) и «triggered» (280px);
* автофокус инпута, подтверждение по Enter;
* используется и как глобальный синглтон, и как локальная обёртка над
  `BottomSheet` через одинаковый набор пропсов.

Во Flutter эквивалента нет: `GlazeBottomSheet.show` одинаков для телефона и
ПК. Практический эффект — на 27" мониторе выбор «Удалить / Переименовать»
выезжает лентой снизу на всю ширину экрана.

**Приоритет: критично** — это самая заметная «мобильность» интерфейса на ПК.

## Что сделано

Реализовано в этой же ветке. Нумерация — по бэклогу §14.

### Каркас

- **ПК-раскладка по умолчанию** (1): `forceMobileLayout` → `@Default(false)`
  (`app_settings_provider.dart`). Схема настроек и её характеризационный тест
  обновлены вместе.
- **Деградация при нехватке ширины** (новое): порог остался 768px, как в Vue, но
  две панели по 280/300px оставляли на контент ~200px — сетка персонажей
  переполнялась. `_fitSidebars` в `desktop_shell.dart` ужимает сначала правую
  панель, затем левую до полосы иконок, удерживая центральной колонке минимум
  420px. Сайдбары рисуются по «эффективной» ширине, сохранённая пользователем
  ширина не трогается.
- **Сброс `navHeightProvider`** (15): включение ПК-режима в рантайме больше не
  оставляет зарезервированную полосу под исчезнувшим навбаром.
- **Миграция `/` → `/characters`** (25) при переходе в ПК-раскладку, не только
  при старте.
- **`goBranch` вместо `context.go`** (23): `shell_navigation_provider.dart`
  публикует `StatefulNavigationShell`, сайдбар переключает ветки как навбар.
- **Без мигания на старте** (§2.3): контроллеры сайдбаров читают
  `SharedPreferences` синхронно, когда те уже готовы.

### Левый сайдбар

- **Порядок и состав** (9): «Персонажи» и «Новый чат» сверху, список, «Глоссарий»
  и «Ещё» снизу — одинаково в развёрнутом и свёрнутом режиме. Кнопка «Новый чат»
  вернулась в развёрнутый режим.
- **Активная подсветка** (10): `DesktopShell` передаёт `currentView`, выведенный
  из маршрута и состояния плавающего окна; «Глоссарий» подсвечивается, пока
  открыт поповер.
- **Hover-glow** (28) вынесен в переиспользуемый `HoverGlow`
  (`shared/widgets/hover_glow.dart`) и применён и в сайдбаре, и в списке чатов.

### Правый сайдбар

- **Инструменты открываются внутри сайдбара** (8): `sidebar_tool_panels.dart` —
  единый реестр пяти инструментов для полосы иконок и хаба;
  `rightSidebarPanelProvider` монтирует панель, повторный тап по иконке
  закрывает её. Кнопка «назад» экранов инструментов уходит через
  `closeExpandedToolScreen` — закрывает панель, а не навигирует всё приложение.
- **Полоса иконок Magic Drawer** (7): у `MagicDrawerPanel` появился режим
  `iconOnly`, использующий тот же список и тот же обработчик тапа, что и сетка
  карточек, — разъехаться они не могут. Полоса работает и в свёрнутом сайдбаре,
  и рядом с открытой панелью.
- **`ToolsScreen(inSidebar: true)`** (§4.5): без отступа под несуществующую
  шапку и без дублирующей заявки на шапку ветки (`publishesShellHeader`).
- **Ширина модальных шитов** (4): `BottomSheetThemeData.constraints` в теме —
  один параметр ограничивает все шиты приложения; на телефонах не срабатывает.
- **`onScrollToMessage`** (19) прокинут через `chatBridgeRegistryProvider`.
- **Иконки** — обычные `IconData` вместо самописного парсера SVG (18).

### Оверлеи

- **Плавающее окно** (11): собственный стек навигации
  (`desktopFloatingStackProvider`), шапка с заголовком/действиями из
  `shellHeaderProvider`, кнопки «назад» и «закрыть», анимация появления, цвета
  из темы. Пункты меню (Настройки, Темы, О программе, Синхронизация, Бэкап)
  идут через `goOrFloat` и остаются внутри окна (5). Бэкап — реальный
  `BackupScreen` вместо заглушки (24).
- **Поповер глоссария** (12): свой заголовок и «назад» даёт вложенный
  `GlossarySheet` (локализованные), фрейм добавляет полосу перетаскивания и
  закрытие; позиция сохраняется, `clamp` защищён от окна меньше поповера (21).
- **Десктопные дропдауны** (6): `shared/widgets/desktop_popup.dart` —
  `showDesktopPopup` с позиционированием у курсора через
  `SingleChildLayoutDelegate` (переворот + прижатие к краям, без оценки высоты,
  которую Vue вёл вручную). `GlazeBottomSheet.show` сам распознаёт «простое меню»
  и уходит в дропдаун на ПК; всё богаче (карточки, сессии, ввод, поиск) остаётся
  шитом. Позицию курсора пишет `PointerPositionTracker` в корне приложения.

### Чат

- **Ширина колонки** (2): настройка `chatMaxWidth` (по умолчанию 900) +
  `ChatColumnWidth` с двумя перетаскиваемыми границами (400–1600px).
- **Кнопка Magic** (14) скрыта на ПК — она открывала пустой отступ, поскольку
  сам drawer на ПК не рендерится.
- **Инлайновый поиск** (20): поле живёт в шапке постоянно, режим поиска следует
  за запросом (`ChatSearchDelegate.syncInlineQuery`), кнопка-переключатель убрана.

### Списки и взаимодействия

- **Адаптивные сетки** (3): `ResponsiveGridDelegate` — аналог
  `repeat(auto-fill, minmax(...))`; применён к персонажам, галерее и подборкам.
- **Правая кнопка мыши** (16) открывает то же, что долгое нажатие: карточки
  персонажей и папок, элементы и группы списка чатов.
- **Escape** (13) закрывает оверлеи изнутри наружу: плавающее окно → поповер
  глоссария → панель сайдбара.
- **Стекло сайдбаров** (17): `DesktopSidebarSurface` на `GlassSurface` —
  прозрачность, блюр и шум из пресета темы; ширина анимируется 220ms, кроме
  времени перетаскивания.
- **Хват ресайза** (26, 27): 8px, вынесен на границу, подсвечивается при
  наведении, двойной клик сворачивает/разворачивает.
- **Переполнения** при узкой центральной колонке: контролы сортировки
  персонажей и пустое состояние лорбуков переведены на `Wrap`.

### Новые зависимости

- **`desktop_drop`** (36): `DesktopFileDrop` принимает карточки персонажей,
  брошенные в окно, и передаёт их штатному массовому импортёру.
- **`window_manager`** (37): `core/platform/desktop_window.dart` восстанавливает
  и сохраняет размер и позицию окна.

### Побочная находка

`ChatWebViewPreloader` строил `InAppWebView` на Linux, где у плагина нет
реализации, — приложение падало на старте красным экраном. Linux добавлен к
существующему исключению для Windows.

## Что сознательно не делалось

- **Пункт 22 (дубликат `ToolsScreen` на `/tools`)** — снят: экземпляр в сайдбаре
  больше не публикует заявку на шапку и не слушает re-tap, так что вреда от
  второго экземпляра нет, а разделять его стоило бы дороже, чем это приносит.
- **Пункты 29–35 (мелкая полировка)** — частично: анимации окна и поповера,
  стекло, скроллбары полосы, курсоры и прокрутка полосы сделаны; отдельная
  реализация тултипов уровня `ToolStripTooltip` (28) не делалась — стандартный
  `Tooltip` покрывает функцию, а его анимация ширины была косметикой.
- **Чат на Linux** не проверялся в рантайме: `flutter_inappwebview` не имеет
  Linux-реализации, поэтому сам экран чата там не работает независимо от этих
  изменений. ПК-раскладка проверена на остальных экранах.
