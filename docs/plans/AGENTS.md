# Агенты вместо Studio

**Статус:** план, кода ещё нет. Основа — исследование в issue #806 и решения
владельца от 2026-11-18.

## Принятые решения

- Studio удаляется целиком: онтология из 10 полос, Studio-пресеты, слоты,
  второй сборщик промпта (`studio-final`), экраны. Студийные пресеты **не
  переносятся** — ни конвертера, ни импорта старых экспортов.
- Остаётся только полезный бэкенд: движок Трекера (Ledger), Post Clean
  (cleaner, аудитор, защита текста, синие под-свайпы), Card Rewriter, батчинг
  запросов, ограничитель параллельности, вспомогательный LLM-клиент.
- Вместо Studio — **агенты в духе Marinara**: главный ответ всегда собирается
  из обычного пресета чата, агенты работают вокруг него.
- Post Clean, Трекер и Card Rewriter становятся **встроенными агентами** новой
  системы.
- **Граница с плагинами:** агенты влияют на генерацию промптами и
  дополнительными проходами модели; плагины расширяют функциональность
  приложения в целом (UI, хуки, код). Агенты не несут исполняемого кода.
- **Сложная модель агента:** промпт агента — список блоков как в обычном
  пресете (роль, порядок, точка вставки, включение), полные переопределения
  параметров генерации, зависимости и подписки на результаты других агентов.
- **Свайп и перегенерация** перезапускают весь пайплайн ответа целиком, со
  всеми агентами. Переиспользование результатов прошлых свайпов — позже.

Сейчас Studio закрыт константой `studioAvailable = false`, а Post Clean,
Трекер и Card Rewriter запускаются только из Studio-ветки
(`PostGenCoordinator` → `CleanerStage` → `LedgerStage` → Card Rewriter).
То есть у пользователей эти три функции уже не работают, и удаление Studio
ничего видимого не отнимает.

## Модель данных

### `AgentDefinition` (таблица `agent_definitions`, библиотека)

| Поле | Смысл |
|---|---|
| `id`, `name`, `description` | Любые; встроенные агенты имеют фиксированный `builtinKind` |
| `builtinKind` | `null` для пользовательских; `post_clean` / `tracker` / `card_rewriter` для встроенных (у них свой движок и свои настройки) |
| `phase` | `pre_generation` / `parallel` / `post_processing` |
| `resultType` | См. таблицу ниже; ограничен фазой |
| `blocks` | `List<PresetBlock>` + `List<PresetBlockFolder>` — тот же формат, что в обычном пресете, редактор переиспользуется |
| `connection` | `chat` (модель чата) / `helper` (общая «модель помощников») / `apiConfigId` |
| `params` | Температура, top-p, max tokens, reasoning и т. д. — каждое с флагом «переопределить» |
| `contextSize` | Сколько последних сообщений видит агент (по умолчанию 5) |
| `cadence` | `everyN` (раз в N ответов), `keywords` + `scanDepth`; пусто = каждый ход |
| `dependsOn` | id агентов, без которых этот не запускается (Continuity → Трекер) |
| `seesOutputsOf` | id агентов, чьи результаты подставляются в его промпт (`{{agent::id}}`) |
| `injection` | Для `context_injection`: точка вставки в главный промпт (depth / роль) или «только через макрос» |
| `settings` | JSON со спецификой типа: запретные слова Post Clean, режим Трекера, порог Card Rewriter, целевой лорбук |
| `order`, `enabled`, `updatedAt` | |

Хранится как JSON в одной колонке плюс индексируемые `id`, `name`, `order`,
`updatedAt` — как сейчас хранятся пресеты.

### Включение по чату

- Флаг в сессии «агенты включены» и список включённых агентов с
  переопределениями для этого чата (модель, частота). Хранить как часть
  `ChatSession` через атомарный метод репозитория либо отдельной таблицей
  `chat_agents (session_id, agent_id, enabled, overrides_json)` — второе
  проще для миграций и не трогает read-modify-write сессии. **Выбор: таблица.**
- Глобальная настройка «набор агентов для новых чатов».
- Глобальная настройка «модель помощников» (одно подключение вместо четырёх
  слотов).

### Журнал запусков (`agent_runs`)

`session_id`, `message_id`, `agent_id`, `phase`, `result_type`, `ok`,
`error`, `output` (текст/JSON), `prompt_tokens`, `completion_tokens`,
`duration_ms`, `created_at`. Нужен для отображения «что агенты сделали на
этом ходу», отладки и бейджа стоимости. Так как свайп перезапускает всё,
журнал не используется как кэш. Чистится вместе с сообщениями.

## Типы результата первой версии

| `resultType` | Фазы | Что делает движок | Было |
|---|---|---|---|
| `context_injection` | pre, parallel* | Текст вставляется в промпт главного ответа (точка вставки или `{{agent::id}}`) и в промпты агентов, подписанных через `seesOutputsOf` | Брифы контроллеров |
| `text_rewrite` | post | Новый синий под-свайп `cleaned`, стрим в пузырь, лицензия на запуск | Post Clean |
| `ledger_update` | post | Отдаётся движку Трекера: операции, снапшот, reconciliation | Studio Ledger |
| `card_update_proposal` | post | Экран ревью правок карточки | Card Rewriter |

\* parallel-агент не видит ответа; его результат уходит в журнал и в
`{{agent::id}}` следующего хода (как у Marinara). Решить в PR 3, нужен ли
parallel в первой версии вообще.

Позже: `lorebook_update` (запись в лорбук с подтверждением), `memory_note`,
`variable_update` (запись в переменные чата).

Встроенные агенты — это `AgentDefinition` с `builtinKind`, засеянные при
первом запуске. Пользователь может менять их блоки промпта, модель, частоту;
движок результата у них свой и не меняется. Можно создать копию встроенного
агента (два разных Post Clean).

## Макросы агентов

Промпт агента собирается тем же движком макросов, что и обычный пресет, плюс:

- `{{agent::id}}` — результат агента на этом ходу (или пусто);
- `{{response}}` — текст ответа (только post-агенты);
- `{{history}}` / вставка последних `contextSize` сообщений как отдельного
  блока-маркера (аналог маркера истории в пресете);
- `{{tracker_state}}` — состояние Трекера.

В главном пресете доступен `{{agent::id}}`; если его нет, `context_injection`
вставляется по точке вставки агента.

## Где агенты встраиваются в генерацию

Один снимок на ход — `AgentTurnPlan` (замена `StudioTurnConfigSnapshot`,
сохраняем идею INV-ST8): список агентов чата с учётом частоты, ключевых слов
и зависимостей, вычисленный один раз в начале хода.

1. **До сборки промпта.** Если в плане есть pre-gen агенты — фаза
   «Running agents…», батчевый запуск (`ControllerBatcher`), результаты
   в `agent_runs`. Pre-gen агенты, подписанные на других pre-gen агентов,
   запускаются волнами по зависимостям. Затем **обычный** `PromptBuilder`
   обычного пресета; вставки передаются в изолят как данные, как сейчас
   `studio_state`.
2. **Во время ответа.** Обычный стрим. Parallel-агенты стартуют вместе с ним.
3. **После фиксации ответа** (`PostGenCoordinator`): сначала цепочка
   `text_rewrite` по `order` (каждый видит текст предыдущего), затем
   `ledger_update`, затем остальные post-агенты параллельно с лимитом.
   Порядок «rewrite → tracker → черновик памяти → теги картинок»
   фиксирован явно: память ждёт часы Трекера, картинки — финальный текст.
4. **Свайп/перегенерация** — тот же путь целиком. Под-свайпы `cleaned`
   и снапшоты Трекера привязаны к свайпу, как сейчас.
5. **Стоп** отменяет всех агентов текущего хода через `genId` /
   `CancelToken`, как остальную генерацию.

Если агенты в чате выключены или план хода пуст — одна проверка в начале,
дальше путь идентичен обычной генерации без агентов.

## Интерфейс

- **Экран «Агенты»** (меню Tools или вместо вкладки «Агенты» в настройках
  API): карточки с именем, фазой, типом, моделью, ценой; создать, копировать,
  импорт/экспорт JSON.
- **Редактор агента**: имя, описание, фаза, тип результата (меняет доступные
  настройки), блоки промпта — переиспользует редактор блоков обычного пресета,
  модель и параметры с переопределениями, частота и ключевые слова,
  зависимости и подписки, настройки типа (для встроенных — их нынешние
  настройки Post Clean / Трекера / Card Rewriter).
- **Лист «Агенты в этом чате»** (настройки чата / боковая панель): главный
  выключатель, тумблеры агентов, переопределения, бейдж «+N запросов за ход,
  ≈M токенов инструкций», «запустить сейчас» для агентов с частотой.
- **Статус хода**: какие агенты работают сейчас; после хода — строка
  «что сделали агенты» с токенами и временем, открывающая журнал и промпт
  каждого агента.
- Все экраны на UI-ките Glaze (`docs/UI_KIT.md`).

переводы. Новые инварианты (вместо INV-ST*): агент видит не больше
`contextSize` сообщений; батч только для одной модели и фазы; план хода
неизменен в пределах хода; rewrite владеет лицензией; порядок
rewrite → tracker → память; стоп отменяет всех агентов хода; выключенные
агенты не дают ни одного лишнего запроса.

## Открытые вопросы

1. **ExtBlocks.** Они уже делают часть работы агента после ответа (Generated,
   Rewrite, Accumulation) и совместимы с внешним форматом расширения.
   Предложение: ExtBlocks остаются как есть (визуальные блоки и совместимость),
   агенты — для влияния на промпт и текст. Rewrite-блок ExtBlocks и Post Clean
   пересекаются; оставить оба.
2. **Где живёт экран «Агенты»:** отдельный пункт в Tools или на месте вкладки
   «Агенты» в настройках API.
3. **Набор агентов для новых чатов:** глобальный, или ещё и на уровне
   персонажа.
4. **Parallel-фаза** в первой версии — нужна или отложить.
