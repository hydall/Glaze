# MemoryBook: короткий гайд

MemoryBook помогает модели помнить старые события длинного чата, не отправляя ей всю переписку при каждом ответе.

## Как это работает

1. Glaze делит старые сообщения на диапазоны и создаёт **черновики**.
2. По кнопке **«Генерировать»** модель превращает диапазон в краткое воспоминание и ключевые слова.
3. Вы проверяете результат, при необходимости редактируете или перегенерируете его.
4. Только после **«Принять»** запись становится активной и может попасть в промпт.
5. Перед новым ответом Glaze ищет подходящие активные записи и добавляет их в контекст модели.

> Черновики с меткой `DRAFT` модель не использует. Рабочая память отмечается `MEM`.

## Безопасные настройки для начала

Откройте **Книги памяти → Настройки** и используйте:

| Настройка | Значение |
|---|---|
| MemoryBook | Включён |
| Режим | **Fast** для простоты или **Balanced** для лучшего локального поиска |
| Автосоздание черновиков | Включено |
| Автогенерация | Выключена |
| Сообщений на черновик | **15** |
| Отставание | **4** |
| Максимум записей в промпте | **7** |
| Бюджет | **Auto** или **Medium** |
| Упаковка | **Hybrid** |
| Место вставки | **Hard Block** |
| Поиск | По ключам; векторный — только после настройки embeddings |

Переключатель автогенерации пока не запускает заполнение черновиков сам. Генерируйте их вручную.

### Что такое отставание

**Отставание** — это число самых свежих сообщений, которые Glaze временно не включает в новые черновики памяти. Например, при значении **4** последние четыре сообщения `user`/`assistant` остаются вне сканирования, а более старые уже можно объединять в черновики.

В первую очередь это снижает вероятность создать воспоминание, пока пользователь ещё выбирает окончательный вариант сцены: генерирует новый свайп, переключается между существующими вариантами, редактирует или удаляет последнее сообщение диапазона. Без отставания память могла бы быть построена по промежуточной версии переписки.

Когда чат продолжается, прежние сообщения выходят из зоны отставания и автоматически становятся доступными для следующего полного диапазона. К этому моменту нужный свайп обычно уже выбран, а последние реплики сцены реже меняются.

Если исходное сообщение всё же удалить после создания памяти, Glaze удаляет связанные с ним черновики и активные записи MemoryBook. При удалении конкретного свайпа удаляется память, привязанная к этому варианту, а ссылки на оставшиеся свайпы корректируются.

Однако обычное переключение на другой уже существующий свайп само по себе память не удаляет и не перестраивает. Поэтому отставание — это профилактика, а не абсолютная защита: оно даёт время закончить свежую сцену и выбрать нужный вариант до создания черновика. Если переключить старое сообщение уже после создания памяти, связанную запись следует проверить, удалить или перегенерировать вручную.

- **0** — черновики появляются быстрее, но выше риск сохранить незавершённый или изменённый обмен;
- **2–4** — безопасное значение для большинства пользователей;
- **6 и больше** — полезно, если вы часто редактируете или удаляете несколько последних сообщений.

Отставание не удаляет сообщения и не скрывает их от обычного чата. Оно влияет только на планирование новых черновиков MemoryBook.

## Обычный рабочий процесс

1. Продолжайте чат. При стандартных настройках новый полный блок появляется примерно после 15 подходящих сообщений, кроме четырёх самых свежих.
2. Откройте **Книги памяти → Черновики**. Если список пуст, нажмите **«Сканировать чат»**.
3. Нажмите **«Генерировать»** у одного черновика или **«Генерировать пакет»**.
4. Проверьте текст и ключи. Исправляйте имена, факты и важные последствия сцены.
5. Если результат плохой, нажмите **«Перегенерировать»**. При ошибке прежний текст сохранится.
6. Нажмите **«Принять»**. Только теперь воспоминание начнёт участвовать в поиске.

## Какой режим выбрать

- **Fast** — базовый современный поиск и ранжирование. Самый предсказуемый вариант.
- **Balanced** — всё из Fast плюс локальный каталог, сущности, темы, эмоции и доступные сигналы значимости. Дополнительного LLM-вызова для поиска нет.
- **Legacy** — старый резервный алгоритм. Используйте только если современные режимы дают заметно худший результат.

Режим влияет на **поиск уже принятых записей**, а не на создание или генерацию черновиков.

Режим **Deep** пока скрыт из интерфейса, потому что находится на доработке. Старые сохранённые значения Deep и Agentic временно безопасно открываются как Balanced.

В завершённом Deep предполагается отдельный вызов LLM, который будет:

- выбирать релевантные воспоминания для текущего контекста;
- консолидировать связанные или дублирующиеся записи;
- предлагать обновление существующих воспоминаний при появлении новых фактов.

Изменения книги не должны применяться незаметно: консолидация и обновление должны проходить через контролируемый workflow с возможностью проверить результат.

## Промпты генерации памяти

В настройках можно открыть полный текст текущего промпта. Встроенные пресеты доступны только для чтения.

Чтобы изменить встроенный пресет:

1. Откройте **«Управление пресетами»**.
2. Выберите встроенный пресет.
3. Нажмите **«Копировать/изменить как новый»**.
4. Отредактируйте копию и сохраните её.

В пользовательском промпте желательно оставить `{{history}}` и потребовать ответ в формате:

```text
Memory: текст воспоминания
Keys: ключ1, ключ2, ключ3
```

## Когда нужен векторный поиск

Ключевого поиска обычно достаточно для начала. Векторный поиск полезен, когда одинаковые события описываются разными словами.

Для него нужны embedding endpoint и модель. После первоначальной настройки нажмите **«Переиндексировать»**. Начальный порог сходства — **0.60**. Переиндексация перестраивает только embeddings и не удаляет записи.

> **Важно:** после любой смены embedding-модели переиндексация **обязательна**. Векторы, созданные разными моделями, находятся в разных пространствах и не должны смешиваться. Пока индекс не перестроен новой моделью, векторный поиск может не находить нужные записи или ранжировать их неправильно.

## Частые проблемы

### Черновики не появляются

- ещё не накопился полный диапазон;
- последние сообщения удерживает настройка отставания;
- эти сообщения уже покрыты другим черновиком или активной записью.

Продолжите чат, уменьшите диапазон или нажмите **«Сканировать чат»**.

### Память принята, но модель её не видит

- оставьте способ вставки **Hard Block**;
- если выбран Macro, в основном prompt preset обязательно должен быть `{{memory}}`;
- проверьте ключи записи;
- временно увеличьте бюджет или число записей.

### Векторный поиск ничего не находит

Проверьте embedding endpoint, выполните переиндексацию и при необходимости временно снизьте порог с `0.60` до `0.50`.

### Память повторяет недавний чат

Оставьте включёнными **«Пропускать уже видимые источники»** и **«Избегать дублей»**.

## Главное правило

MemoryBook не является полностью автоматическим архивом. Лучший результат получается, когда пользователь просматривает черновики, исправляет ошибки и принимает только полезные воспоминания.
