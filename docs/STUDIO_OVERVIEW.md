# Studio: как несколько моделей собирают один ответ

Studio разделяет генерацию между специализированными областями ответственности. Контроллеры анализируют контекст и готовят краткие рекомендации, Main Writer пишет сцену, Post Clean при необходимости редактирует её, а Studio Ledger обновляет каноническое состояние.

Топологию больше не определяют режимы Direct, Assisted или Legacy. Единственный актуальный механизм — переключатели агентов в выбранном Studio preset. Включённые контроллеры запускаются перед генерацией; выключенные не участвуют в ходе.

## Агенты Studio

В текущей ontology есть 10 фиксированных lanes в порядке пайплайна:

| Lane | Ответственность |
|---|---|
| **Continuity** | Факты, последовательность событий, физическое состояние, знания персонажей и незавершённые линии. |
| **Agency & Character** | Суверенность пользователя, автономия, психология и правдоподобное поведение персонажей. |
| **Dialogue** | Доля и ритм диалога, право персонажей говорить, голос, паузы и формат реплик. |
| **Anti-Loop RU** | Повторы, клише, нежелательные обороты и структурное разнообразие русской прозы. |
| **Anti-Loop EN** | Те же проверки для английской прозы. |
| **World/NPC** | Активность мира и NPC, внешнее давление и фоновые последствия. |
| **Meta-Weaver/OOC** | Политика мета-персоны и OOC: ответить, добавить периодическую заметку или остаться безмолвной. По умолчанию выключен. |
| **Main Writer** | Финальная видимая проза. Всегда включён и не может быть отключён. |
| **Post Clean** | Постобработка: аудит, исправление локальных несоответствий, повторов и клише, применение визуального состояния. |
| **Studio Ledger** | Извлечение и сохранение текущего канонического состояния сцены, мира, отношений и сюжетных линий. |

Переключатели являются единственным средством выбора топологии. В частности, нет скрытого набора контроллеров, который включается названием режима. Каждый включённый pre-generation controller запускается каждый ход; старые per-agent cadence и keyword gates больше не управляют запуском.

## Основной пайплайн

```text
Контекст и память
        |
        v
Включённые pre-generation controllers
        |
        v
Main Writer
        |
        v
Postprocessing / Post Clean
        |
        v
ExtBlocks
        |
        v
Studio Ledger
```

### 1. Контекст

Перед вызовами собираются карточка и персона, история чата, lorebooks, MemoryBook, текущее состояние Ledger и другие разрешённые части prompt context. Контроллеры получают ограниченный контекст и формируют компактные briefs, а Main Writer получает предназначенный ему полный контекст вместе с этими briefs.

### 2. Pre-generation controllers

Все включённые агенты фазы `pre_generation`, кроме финального, становятся контроллерами. Они сортируются по `order`, могут объединяться в совместимые batch-запросы и возвращают рекомендации, а не готовую сцену.

`ControllerPhaseRunner` владеет этой фазой: разрешает preset, отделяет фазы, проверяет cache, группирует запросы и собирает briefs. Ошибка обязательного controller run останавливает Studio-цикл вместо тихого продолжения с неполным набором рекомендаций.

### 3. Main Writer

Main Writer всегда включён. `StudioActivationGate` сначала ищет среди enabled pre-generation agents спецификацию с `isFinal: true`. Для миграционной совместимости старых preset без такого признака используется последний включённый pre-generation agent; если pre-generation agents нет, fallback выбирает последнего включённого агента вообще и не запускает его повторно как post-processing.

Main Writer создаёт видимый ответ, используя исходный контекст и briefs включённых контроллеров. Именно его reasoning и streaming передаются в основной UI.

### 4. Postprocessing и Post Clean

После Main Writer `MemoryStudioService` последовательно запускает включённые
generic-агенты фазы `post_processing`. Их непустой успешный результат заменяет
текущий текст для следующего шага. Встроенные `post_clean` и `ledger` также
имеют отдельные durable стадии ниже; эту двойную форму ownership следует
считать текущим compatibility path, а не приглашением добавлять ещё один
параллельный запуск.

Отдельный `CleanerStage` владеет канонизацией ответа в чате. Он может запустить Character & World Auditor, создать и заполнить cleaned sub-swipe, сохранить partial result при некоторых сбоях и выбрать итоговый текст. Запрещённые слова и требования к стилю передаются модели инструкциями, а не удаляются безусловным строковым фильтром.

**Beauty не является отдельным shard или controller lane.** Визуальное состояние загружается, назначается аудитом/cleaner и сохраняется `CleanerStage` в session variables. Post Clean применяет это состояние и может вернуть обновлённый `<glaze_beauty_state>` marker.

### 5. ExtBlocks

После выбора итогового текста `CleanerStage` запускает ExtBlocks для выбранной пары `swipeId` и `agentSwipeId`. Если cleaner отключён или не изменил текст, блоки привязываются к исходной финальной версии. Подробнее: `docs/EXTBLOCKS_OVERVIEW.md`.

### 6. Studio Ledger

Ledger запускается после ExtBlocks и получает окончательный cleaned, исходный fallback или сохранённый partial text. Он не должен записывать состояние по pre-cleaner черновику. Ошибка Ledger не превращает уже полученный ответ чата в ошибку.

## Память Studio

### MemoryBook

`MemoryBook` — отдельная эпизодическая долговременная память. Она хранит записи о произошедших событиях и подбирает релевантные воспоминания для будущих сцен. Это скорее журнал эпизодов, чем точная таблица текущего состояния.

### Studio Ledger

`Studio Ledger` хранит компактное текущее каноническое состояние: кто присутствует, где и когда идёт сцена, какие факты установлены и какие линии остаются открытыми. Состояние живёт в tracker rows, а snapshots обеспечивают provenance, rollback и безопасность свайпов.

Ledger также поддерживает reconciliation принятого диапазона истории. Этот процесс сверяет накопленное состояние с выбранными сообщениями и применяет подтверждённые операции атомарно после повторной проверки полномочий.

### Character Knowledge Facts

Отдельный слой хранит атомарные сведения о знаниях и развитии персонажей. Предварительные состояния подтверждаются принятой веткой истории, чтобы регенерация и переключение свайпов не превращали отвергнутый вариант в канон.

## Владение кодом

| Компонент | Роль |
|---|---|
| `StudioActivationGate` | Делит enabled agents на pre-generation, final и post-processing; выбирает Main Writer по `isFinal` с legacy fallback. |
| `ControllerPhaseRunner` | Выполняет общую pre-generation фазу: preset, split, cache, batching, вызовы и сбор briefs. |
| `MemoryStudioService` | Session-bound оркестратор: запускает controllers, Main Writer и post-processing agents, возвращает `StudioPipelineResult`. |
| `CleanerStage` | Владеет post-generation канонизацией сообщения, cleaner/auditor, Beauty state и порядком `ExtBlocks -> Ledger`. |
| `StudioLedgerService` | Тонкий facade без `Ref`: формирует запросы к специализированным ledger-компонентам и дедуплицирует in-flight операции. |
| Ledger specialists | `LedgerTurnRunner` и `LedgerTurnCommitter` обслуживают обычный ход; `LedgerReconciliationRunner` и `LedgerReconciliationCommitter` — reconciliation; `LedgerPromptFactory`, `LedgerOutputRecovery`, `LedgerOpApplier`, `LedgerCanonAuthority`, `LedgerReplacementBasisResolver`, `LedgerRunDiagnostics` и `LedgerInFlightRegistry` разделяют prompt, recovery, применение операций, canon/provenance, diagnostics и concurrency. |

## Важные свойства

- Main Writer всегда включён; пользователь управляет остальными lanes переключателями.
- Meta-Weaver/OOC по умолчанию выключен.
- Controller briefs являются рекомендациями и ограничениями, а не текстом для копирования в сцену.
- Post Clean может быть выключен; ExtBlocks и Ledger при этом всё равно получают исходный финальный ответ по отдельной ветке `CleanerStage`.
- Character & World Auditor диагностирует проблемы для cleaner и не является отдельным Writer.
- Beauty принадлежит cleaner pipeline, а не отдельному агенту.
- ExtBlocks выполняются до Ledger; Ledger читает уже выбранный пользователем текстовый вариант.
- MemoryBook и Studio Ledger — разные подсистемы: эпизодическая память и текущее каноническое состояние соответственно.

## Глоссарий

| Термин | Определение |
|---|---|
| **Studio** | Система специализированных LLM-проходов с топологией, задаваемой переключателями агентов. |
| **Lane** | Фиксированная область ответственности агента в Studio ontology. |
| **Controller** | Включённый pre-generation agent, который создаёт brief, но не пишет сцену. |
| **Brief** | Компактные факты, риски и ограничения, передаваемые Main Writer. |
| **Main Writer** | Обязательный final agent с `isFinal: true`, создающий основной ответ. |
| **Legacy fallback** | Выбор последнего enabled pre-generation agent, если старый preset не содержит корректного `isFinal`. |
| **Post Clean** | Постобработка и cleaner-owned редактура финального ответа. |
| **Beauty state** | Сохраняемые визуальные правила, которыми владеет cleaner pipeline. |
| **ExtBlocks** | Дополнительные инфоблоки, изображения, JavaScript и интерактивные панели после финализации текста. |
| **MemoryBook** | Эпизодическая долговременная память о произошедших событиях. |
| **Studio Ledger** | Компактное каноническое состояние текущей сцены и её сущностей. |
| **Reconciliation** | Проверка диапазона принятой истории и согласование Ledger с ним. |
| **Character Knowledge Fact** | Атомарный факт о знаниях или изменении персонажа с привязкой к принятой истории. |
